# 餐厅座位分配系统（自助小火锅）— P1 原型设计

日期：2026-08-16
状态：已实现（`../index.html`，单文件 HTML，零依赖）
来源：前序设计讨论（`../session.jsonl` 第 1–3 轮）经用户确认后的 P1 落地

## 1. 定位与形态

- **系统是店员的"记忆体 + 参谋"**：所有决策以"可选方案 + 推荐"形式呈现，店员确认后执行，系统不自动替店员做决定。
- **技术形态（用户已确认）**：单文件 HTML 网页，双击即开、离线可用、零部署；座位数据持久化在浏览器 `localStorage`（key: `seat-alloc-v1`），刷新/关店重开不丢。
- **布局模型（用户已确认）**：排式座位（若干排 × 每排若干座），支持排名称（A区/靠窗/第N排）与每排座数编辑；贴合自助小火锅"一排一排坐"的店型。

## 2. 核心交互流（用户设想 → 实现）

| 用户设想 | 实现 |
|---|---|
| 先设置餐厅座位布局 | 「⚙️ 布局设置」：增删排、改排名称/座数、恢复演示布局；保存后按座位号保留已有占用 |
| 每次来客人，店员输入客人数 | 「🪑 来客入座」：人数步进器 + 快捷按钮（1–6）+ 可选备注 |
| 系统给出所有符合条件的位置 | 计算每排**连续空区间**，列出所有能装下该人数的区间（方案 1..n），座位图上全部蓝色高亮 |
| 选择其中一个 | 点座位图高亮区或下方方案条任一项 → 确认框显示具体座位号 → 确认入座 |
| 之后这几个位置显示有人 | 落座座位变红色并显示人数；头部统计实时更新占用数 |

## 3. 数据模型

```
layout       [{ id, label, seats }]                    排布局
seatStates   { "r1#0": { st: "free"|"occ"|"clean",
                         party?, until? } }            座位状态（until = 清理完成时刻）
parties      { p1: { id, size, note, seatedAt,
                     seatKeys[] } }                     在座桌
queue        [{ id, size, note, since }]                排队队列
cleanMin     number                                     默认清理倒计时（分钟，默认 3）
```

## 4. 算法

- **连续空区间**：逐排扫描，收集 `st === 'free'` 的连续 run。
- **候选方案**：`len >= k` 的所有区间；推荐 = **最小能装下的区间（best-fit）**，减少碎片。
- **块内贴边入座**：在同一空块内从**左端起坐**（块内不在中间坐），剩余部分保持完整连续，留给更大的桌——一条客人无感、但消灭大部分碎片问题的规则。
- **排队喂座**：空位释放合并后，队列中能装下的桌可一键进入选位流程；同类（同人数）按先来先服务（`since` 升序）显示。
- **离座 → 清理 → 空**：离座默认进入清理倒计时（可改 3 分钟 / 立即空），倒计时结束自动变空并与相邻空位合并；清理中可手动"完成清理"。

## 5. 页面结构

- 头部：统计（总/空/占用/清理中/排队）+ 工具栏按钮
- 座位图：每排一行，座位方块（空=浅灰、占用=红、清理=琥珀倒计时、候选=蓝、推荐=蓝底★）
- 右侧排队面板：人数、已等时长、安排入座 / 移出
- 底部方案条：选位模式下展示全部候选方案，★ 标注推荐
- 模态框：来客入座、确认入座、座位操作（离座/清理）、无空位（引导加入排队）、布局设置

## 6. 已验证的边界情况

- 无任何连续空位 → 提示"没有能连坐的空位"并引导加入排队
- 队列中客人始终排在选位流程之前（有空位时按钮亮起）
- 布局修改删除被占用座位 → 该桌释放并提示店员重新安排
- 清理倒计时到期自动释放；重置今日清空占用/清理/排队、保留布局

## 7. 后续（P2–P4 已实现）

- **P2 拆坐（已实现）**：`splitSeating` 配置开关（布局设置里勾选，默认开）
  - 无整块时给出拆坐方案：部分数最少、间距最小（如 `4 = 2+2`、`3 = 2+1`），弹窗一次征询
  - 拆坐桌标记 🔗，座位图角标显示；出现 ≥ 人数的大块后自动出"可合并到 X 区 Y-Z 号"提示条
  - 合并需整桌同意（原子整桌移动）；「客人拒绝」后写入 `refuseMerge`，该桌不再提议
- **P3 移位拼座（已实现）**：`shiftSeating` 配置开关（高峰期可选模块，默认开）
  - 算法：模拟占用集合，搜索移动 1–2 桌（整桌、原子）拼出 ≥ 人数的连续块；评分 = 移动桌数最少 → 移动距离最短 → 块浪费最小
  - 触发点：来客无整块时的"移位拼座"方案、排队桌"📦 移位拼座"按钮
  - 征询：确认弹窗列出每桌移动（原位置 → 目标），任一桌「这桌拒绝」→ 整案取消并写入 `refuseShift`（不再提议该桌）；「免打扰🚫」由桌弹窗一键打标，移位方案永不包含
  - 执行后自动进入该人数选位模式（拼出的块作为方案呈现）
- **P4 数据调优（已实现）**
  - **事件日志**：全量记录 arrive/seated/queue_join/queue_drop/leave/clean_done/split/merge/merge_refuse/shift/shift_refuse/reset，带时间戳，上限 3000 条
  - **营业统计看板**（📊 统计）：今日接待桌数/人次、平均就餐时长、当前上座率、平均/P90 等待、拆坐/合并/移位次数与拒绝数、当前空区间分布、建议接受率
  - **等待预估**：排队桌显示"预计 X 分钟"（按平均就餐时长模拟未来离座，估算何时凑出 ≥ 人数的连续块）
  - **离线仿真对比**：用今日真实到店序列在 4 套配置（全关/开拆坐/开移位/全开）下重放，对比接待数、平均等待、排队滞留、末态上座并给出综合最优；实现 = 交换全局 state + SIM 旁路标志复用全部算法，跑完自动还原，零污染（浏览器实测验证）
  - 验证：32 项逻辑测试 + 真实浏览器全流程（预估显示 → 统计卡片 → 仿真表 → 状态无污染）
- **远期（未实现）**：分时段到达预测（需多日历史数据）、预测驱动的模块开关提示

## 8. 遗留问题（需店方确认的配置）

① 实际座位布局（几排、每排几座，可在布局设置里直接改）
② 是否一人一锅（决定 P2 拆坐开关默认值）
③ 是否限时（影响就餐时长分布）
④ 高峰时段（决定 P3 移位模块开关时段）
